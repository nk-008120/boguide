Ingested IBO 2016 Theoretical A (50 questions, 4 T/F statements each) into BiOrchive, following .claude/skills/ibo-paper-ingestion, from the two newest files in the user's Downloads folder. Unlike prior papers (2015 A/B), the exam PDF had clean, fully-extractable text (PyMuPDF) and a reliable 'Q.N' header per question -- extract.py ran cleanly with --question-regex '^Q\.(\d+)\b'. The solutions PDF, by contrast, is OCR-quality/letter-spaced and garbled throughout (e.g. 'Weel' for 'Wee1', 'I R Q 2 Q 1 6' for running headers). Built answers.csv from the solutions PDF's own compact answer-key table (page 2, clean checkmark grid, all 50 questions) rather than the per-question inline 'Answer key:' lines, then cross-verified every one of the 200 statements against those inline lines programmatically (position-based extraction spanning page breaks, tolerant to OCR letter-spacing). Found 13 disagreements; resolved each independently by re-deriving the answer from the actual source figure/data (rendered at high DPI) or first-principles biology reasoning, not by trusting either source blindly -- 12 of 13 confirmed the compact table was right (the inline explanation text for those had duplicated/misattributed content from an adjacent statement or question, e.g. Q2's given explanation for statement C was actually a near-duplicate of statement D's), and one (Q18 statement D) was corrected the other way, from the table's TRUE to FALSE, after tracing the actual PV-loop figure. Also found a genuine content-swap defect in the solutions PDF distinct from the above: its own 'Q.23' slot contains an entirely unrelated question (bat/bird digestive and respiratory physiology) that does not match the exam PDF's real Q23 (phlorizin/SGLT2/diabetic mice) -- Q24 realigns correctly immediately after, so this is an isolated one-question substitution, not a systematic offset; Q23's explanations were written from independent physiology reasoning rather than the mismatched source text. Figures: extract.py's raster-image extraction returned mostly unusable fragments for this paper (single-pixel-wide vector-rendering artifacts, tiny gradient-fill tiles from shaded diagram elements) rather than real standalone images, for all but 3 questions (Q2, Q3, Q5, confirmed as genuine embedded photos/gels). For the other 32 figure-bearing questions, since the exam PDF's text is genuinely reliable here (unlike 2015), used a text-bounding-box heuristic (first large vertical gap after the question header = end of stem prose; next 'Fig./Figure/Table Q.N' caption line or the 'Indicate in the Answer...' line = bottom bound) to auto-detect and render clean full-figure crops directly from the exam PDF at 250dpi, batch-reviewed via labeled contact sheets before trusting them. Two questions (Q33, Q46) needed a data table rendered as part of the figure crop (not just a chart) since the table itself is the answerable content. After the initial assemble.py run passed validate.py, a manual scan of every rendered content page against its own stem text caught 2 stems (Q6, Q8) that referenced 'the table below' in prose but never actually included that table -- both had a second data table (Table Q.6 fatty-acid composition; Q8's amino-acid mass reference table) that got summarized in prose but not transcribed; fixed both explanations.txt and the already-generated content pages directly rather than re-running assemble.py (which only appends and would have duplicated all 50 entries). All 50 questions pass validate.py clean; spot-checked in a live Hugo server (figures render, both newly-added tables render, quiz scores correctly with explanations, prev/next nav at both sequence boundaries, round/year/question-bank listings and the topic-graph subject taxonomy all pick up the new round automatically, no subject tags fell outside the existing master list or topic-graph.json).
