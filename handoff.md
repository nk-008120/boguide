## What's proven to work — apply directly, don't re-derive

**1. Depth bar ("IBO level")**: roughly first-year-university depth, not high-school survey. Named cell types/structures with their specific roles, staged/timed processes, specific mechanisms — not generality. Every section should teach something a diagram alone can't.

**2. Page structure**: one subdirectory + `_index.md` per topic, never a monolithic tabbed single-file page, all as **direct children of the section's `_index.md`** (flat, not nested). **Split further whenever a topic is too dense to share a page** — happened repeatedly in Animal Anatomy and shaped Biosystematics' tiering too (Phylogenetics split into Cladistics + Molecular Systematics rather than one page). Don't force a pre-committed page count — propose a breakdown, but expect it to shift once you're actually writing.

**3. Standard page template** (front matter + body section order), reuse verbatim:
```yaml
---
title: "..."
weight: N
description: "..."
difficulty: "beginner" | "intermediate" | "advanced"
prerequisites: ["Other-Page-Directory-Name"]   # sibling directory names, resolved to links by topic-meta
syllabus_tags: ["IBO", "USABO", "<subject-specific-tag>"]
---
{{< topic-meta >}}

## Overview
## Key Concepts
## Comparative Structures        (rename/repurpose if the subject doesn't have a natural structural-comparison axis — Biosystematics kept the heading but used it for concept-comparison tables instead; see above)
## Common Exam Questions
## Visual Reference
## Practice Problems
```
The `{{< topic-meta >}}` shortcode (`layouts/shortcodes/topic-meta.html`) needs no changes — reads `difficulty`/`prerequisites`/`syllabus_tags`, resolves prerequisite links via `.Page.Parent.RelPermalink` + lowercased directory name. Cross-section links (e.g. Biosystematics → Animal Anatomy) work as plain relative markdown links (`../../2-animal-anatomy/body-plans/`) — confirmed building clean, not just same-section links.

**4. Section landing page (`_index.md`) front matter has no `difficulty`/`prerequisites`/`syllabus_tags`** — just `title`, `weight` (matches the section directory's numeric prefix, e.g. `4-biosystematics` → `weight: 4` — confirmed by checking sibling sections), and `description`. Body is a short "How this section is organized" writeup explaining the tiering logic, then `{{< cards cols="N" >}}` grids grouped under `###` sub-headings per tier — see `content/resources/4-biosystematics/_index.md` or `2-animal-anatomy/_index.md` for exact syntax. Not every subject will have clean tiers or a fixed ratio — Animal Anatomy used 5:3:2 (human/vertebrate/invertebrate weighting specific to IBO's anatomy emphasis), Biosystematics used 4 roughly-even tiers (Foundations/Phylogenetics/Classification Survey/Practical) instead. **Propose the tiering for each new subject on its own terms — don't reuse a prior section's ratio or tier count.**

**5. Visual Reference format** (the part that took two rounds of user correction in Animal Anatomy — follow this exactly, don't regress to the sparse version):
```markdown
## Visual Reference

**Interactive**

- **Named concept (library/technique)** — what the user manipulates, and specifically what it teaches that a static image can't. Plotly for quantitative graphs, plain SVG/HTML/CSS/JS for click-through/hover-to-reveal (no new library), Mermaid (native fenced code blocks) for relationship/flow diagrams.
- *(at least one interactive item is a hard requirement per page)*

**Static**

- Specific, named diagrams (not vague), several cross-referenced to the interactive item they pair with.
```
Animal Anatomy pages ended up with 5-7 static items each; Biosystematics pages landed in the same range. Diagrams/interactives remain **specifications only** — no images downloaded, no JS/Plotly actually built, in any section so far. Keep it that way unless the user explicitly asks otherwise in the new session (downloading needs per-file permission: filename, source, size).

Optional third category, added for Ethology and worth reusing for any subject where behavior/process is dynamic enough that a still image undersells it: **`<!-- VIDEO: [behavior] — [species] — [what it shows that a static diagram can't] -->` HTML-comment markers**, placed in `## Visual Reference` and inline in body text at the relevant point. Same specification-only rule applies — markers only, nothing sourced or embedded. Not part of the default template; only add this category if the subject warrants it or the user asks.

**6. Tone/prose pattern**: dense paragraphs, not bullet-fragment notes. Bold key terms on first use. Cross-link liberally — within-section (`[Page](../sibling-page/)`) and across sections where genuinely relevant (`[Page](../../2-animal-anatomy/some-page/)`). Before citing another page's content in a cross-link, **verify the claim is actually covered there** (grep the target file) — one such false claim was caught and fixed during Biosystematics (a chloroplast-endosymbiosis cross-link to a Body-Plans page that didn't actually cover it), and another during Ethology (see below). **When a claim doesn't check out, fixing/expanding the existing target page is an equally valid response, not just rewording or dropping the link in the new page** — the user has explicitly given standing permission to rewrite already-published pages for this kind of correctness fix, so don't default to only ever touching the page currently being written.

## Site-wide facts worth knowing before writing

- **Math**: KaTeX via Hextra's default (`params.math.engine`), `$...$`/`$$...$$` delimiters. **Do not** hardcode a MathJax `<script>` tag the way 5 legacy files do (`1-cell-molecular/_index.md`, `1-cell-molecular/Biochemistry/_index.md`, `10-bioinformatics/_index.md`, `14-practical-4/_index.md`, `8-ecology/_index.md`) — known unfixed bug in old content, not a pattern to copy.
- **Sidebar**: fully automatic from content-tree structure + `weight`, confirmed working across both finished sections with zero `hugo.toml` edits. Do not touch `hugo.toml`'s `[menu]` section.
- **No "coming soon" section directories remain.** `content/resources/5-plant-physiology/` (formerly the last stub) is now complete — see above. Every directory under `content/resources/` (1-15) has real content.
- **Landing page pattern**: see point 4 above — short intro + tiered `{{< cards >}}` grids. Ask the user what the natural internal structure of the new subject is before assuming a ratio or tier split; don't default to a prior section's split.
- **Image convention** (once sourcing is approved): flat per-topic directory under `static/`, e.g. `static/ANATOMYPICS/` (precedent: `ECOLOGYPICS`, `MCBBPICS`, `BIOINFOPICS`), referenced as `![Alt text](/DIRPICS/filename.png)` with an attribution line immediately after (`*Source: OpenStax Biology 2e, CC BY 4.0*` or Wikimedia Commons equivalent).
- **No CI/build pipeline exists** — verify content changes with `hugo --minify --destination <tmp-dir>` (Hugo v0.162.0 installed, confirmed working). Note: on this Windows/Git-Bash setup, a bare relative `--destination` can fail with an access-denied error depending on cwd — pass an absolute path (e.g. into the scratchpad dir) instead. After building, grep the generated HTML for `resources/` hrefs in the new pages and confirm each target `index.html` actually exists — this caught real mistakes during Animal Anatomy and is worth repeating every time, not just once. Two build-output quirks confirmed again during Plant Anatomy, worth knowing before writing the grep: (1) the `--minify` flag strips quotes from attributes that don't need them, so generated hrefs render as `href=/resources/...` with no surrounding quotes — a grep pattern requiring `href="..."` will silently match nothing; match on `href=/resources/[^ >"]*` instead. (2) output directories keep the content folder's numeric prefix (e.g. `public/resources/6-plant-anatomy/...`, not `public/resources/plant-anatomy/...`) — don't guess the slug, `ls` the built `resources/` directory first.
